### Introduction

Your first project doesn't involve any code. You'll write the study plan you'll follow for the next year: when you'll study, how many hours, what you're aiming for, where you'll go for help, and how you'll stay accountable.

This sounds less exciting than building something, but it's one of the best predictors of whether you finish. A written plan turns "I'll study when I have time" into specific hours on specific days. It also gives you something to check yourself against when motivation runs low.

You'll write the plan as a Markdown file on your computer. **Markdown** is a simple way to format plain text: a line starting with `#` becomes a heading, a line starting with `-` becomes a bullet point. You'll use Markdown for every README you write in this curriculum. In the "Hello, GitHub" project at the end of the Git section, you'll publish this file as the first thing in your public learning journal, so write it as something you're happy for others to read.

### Before you start

- You don't need any tools beyond a plain text editor. On macOS that can be TextEdit (choose Format > Make Plain Text); on Windows, Notepad; on Linux, whatever text editor came with your system. You'll install a proper code editor in the next section.
- Create a folder called `mimir-learning-journal` somewhere easy to find, such as your home folder or Documents. Inside it, create a file called `learning-plan.md`. You'll start every project's name with `mimir-`, so your portfolio projects are easy to spot on your GitHub profile.
- Have your rewritten question from the "Asking for Help" assignment ready.
- Skim [the basic Markdown syntax on GitHub Docs](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax). You only need headings, lists, bold text and links for now.

Here's a skeleton to start from. Replace every part of it with your own content.

```markdown
# My Learning Plan

## Why I'm doing this

## My goal

## Weekly schedule

## Where I'll ask for help

## Accountability

## A question, asked well
```

### Assignment

<div class="lesson-content__panel" markdown="1">

1. **Why I'm doing this.** Write two to four sentences about why you want to build AI systems. Be honest and specific. "I want a better-paid job where I build things" is more useful on a hard day than "AI is the future."
1. **My goal.** Pick one target role from the About page (for example, AI Engineer or Agent / Automation Engineer) and a target date to finish the curriculum.
   - Work out the date from your weekly hours: the main paths total roughly 1,340 hours, plus about 120 if you take the ML Foundations elective. At 15 hours a week, 1,340 hours is about 89 weeks. Show this calculation in your plan.
1. **Weekly schedule.** Write a table or list with the specific days and times you'll study each week, and the total hours.
   - Include at least four study sessions per week.
   - Be realistic. A plan of 8 hours you'll actually do beats 25 hours you won't.
   - Add the sessions to your real calendar as recurring events.
1. **Where I'll ask for help.** List at least two places you'll go when you're stuck (for example, an AI chatbot for explanations, and a specific community or person for feedback), and when you'll use each.
   - Include your personal "stuck rule", such as "I'll try for 20 minutes, then ask."
1. **Accountability.** Describe the accountability method you set up in "How This Curriculum Works": who or where, and how often you'll check in.
   - Add a weekly check-in log section at the bottom of the file and make your first entry today.
1. **A question, asked well.** Paste your original and rewritten questions from the "Asking for Help" assignment.
   - Label which parts of the rewrite are the goal (X), what you did, what you expected, what happened, and what you tried.
   - Add one sentence explaining what the XY problem would have looked like for this question.
1. Keep the file in your `mimir-learning-journal` folder. You'll put it on GitHub with a README in the "Hello, GitHub" project. For now, show it to your study partner or someone you trust and ask whether the schedule looks realistic for your life.

#### Extra credit

- Track your actual study hours for the first two weeks in the check-in log, then compare them with your plan and adjust the schedule. Note what you changed and why.
- Add a "Risks" section: the two things most likely to make you stop (a busy season at work, a new baby, burnout) and what you'll do when each happens.

</div>

### Submitting your work

You'll publish this plan in the "Hello, GitHub" project, so for now "submitting" means it's finished and saved. A strong plan:

- Has specific days, times and a weekly hour total, not "evenings when I can."
- Shows the target-date calculation, so you can redo it if your hours change.
- Names real places to get help and a concrete stuck rule.
- Includes a rewritten question that states the real goal and would make sense to a stranger.
- Already has its first check-in log entry, which proves you've started using it.
