### Introduction

Welcome to Project Mímir. This curriculum takes you from never having written a line of code to building AI agents: software that uses language models and tools to complete multi-step work on its own. It is free, open source, and built around one idea: you learn to build things by building things.

This first lesson is the map. Before you write any code, you should know how the curriculum is organized, what a typical lesson and project ask of you, what it will cost, and how to keep going when it gets hard. Read it carefully. Many people who quit self-taught programs don't quit because the material was too hard. They quit because they didn't know how to use it.

### Paths, sections and lessons

The curriculum is a single route, divided into **paths**. Each path is a large chunk of skill, and they are meant to be done in order:

1. **Foundations** (about 260 hours): the terminal, Git, Python, working with data, working with AI coding assistants, how the web works, how language models work, and your first app that calls a model.
1. **AI Engineering Core** (about 380 hours): prompting, evals (tests that measure whether an AI system actually works), structured outputs, the machine learning basics every AI engineer needs, backends, retrieval (often called RAG) and a real frontend.
1. **Agentic Systems** (about 300 hours): building agents, giving them tools, connecting them to other systems, securing them and evaluating them.
1. **Production & LLMOps** (about 180 hours): deploying, observing and scaling what you build.
1. **ML Foundations** (about 120 hours, elective): how models are trained, serving open models, and fine-tuning one yourself.
1. **Final Capstone** (about 120 hours): a real project for real users.
1. **Getting Hired** (about 100 hours): turning your portfolio into a job.

Each path is split into **sections**, such as "Git & GitHub" or "Python Fundamentals", and each section contains a handful of **lessons** followed by a **project**. At 15–20 hours a week, the required paths take roughly 16–21 months. Those numbers are guides, not deadlines. Some lessons will take you an evening; some will take a week. Both are normal.

If you already code, you don't have to read every Foundations lesson. Try the Foundations projects instead. If you can build them comfortably, move on to the next path.

### How a lesson works

Every lesson follows the same layout, so you always know where to look:

- **Introduction** and **Lesson overview** tell you what the lesson covers and why it matters.
- The **teaching sections** explain the ideas in plain language, usually with short code examples. Type the examples out yourself instead of copying them. Your fingers learn things your eyes skip.
- The **Assignment** is a numbered list of readings, videos and exercises. These are the best free resources we could find, and they go deeper than the lesson text. Do them. The lesson text is the summary; the assignment is where most of the learning happens.
- **Additional resources** are optional. Use them when a topic clicks and you want more, or when it doesn't click and you want a second explanation.

### How projects work

Projects are the heart of the curriculum. Every few lessons you will build something real: a quiz game, a weather tool, a chatbot, and later, agents that do actual work. Each project page tells you what to build, gives you requirements, and offers extra credit if you want to push further.

Two rules apply to every project:

- **It goes on GitHub.** GitHub is a website that hosts code. In the "Git & GitHub" section you'll learn to publish your work there. By the end of the curriculum, your GitHub profile will be a portfolio that shows employers what you can do, project by project. That's what "building in public" means here: your work, including the early, rough work, is visible.
- **It has to prove it works.** A project isn't done when the code exists. It's done when you can show it works: a test that passes, a measured number, a short demo. You'll get better at this as you go, and by the AI Engineering Core path it becomes the main skill.

If a project feels too hard, it's probably the right size. Struggling with a problem for a while, then solving it, is how the knowledge sticks.

### Using AI as a tutor, not a ghostwriter

You're learning to build with AI, so of course you'll use AI while you learn. The question is how. A good rule: **use AI to understand, never to skip understanding.**

Good uses of a chatbot or coding assistant:

- "Explain this error message to me like I'm new to Python."
- "What does the `-r` flag do in `rm -r`?"
- "Here is my code. Don't fix it. Tell me which line is wrong and give me a hint."
- "Quiz me on what I just learned about Git branches."

Uses that will hurt you:

- Pasting a project's requirements and submitting what comes back.
- Accepting code you can't explain line by line.

The test is simple: could you rebuild it tomorrow without help? If not, you didn't learn it, and an interviewer or a production bug will find that out. Later in the curriculum you'll use coding agents heavily, on purpose, once you can judge their output. Until then, write the code yourself.

### What it costs

The curriculum is free. Your tools mostly are too: Python, VS Code, Git and GitHub cost nothing. Starting in the "Your First LLM App" section, projects call language model APIs (services you pay per use), and most projects cost a few dollars of usage at most. You'll learn to measure and cap that cost. If money is tight, free tiers and local models cover nearly everything. [Ollama](https://ollama.com/) runs open models on your own computer at no cost, and you'll see how to use it as a fallback when you get there.

### Tracking progress and staying accountable

Each lesson has a "Mark as complete" button. It saves to **this browser only**. Clearing your browser data or switching devices resets it. Treat it as a convenience. The record that counts is your GitHub history.

Self-paced study is lonely, and loneliness is a common reason people stop. Project Mímir doesn't have an official community chat yet, so build your own accountability habit:

- **Find one study partner.** A friend, a coworker, someone from a local meetup. Agree to tell each other what you finished each week.
- **Join an existing beginner community.** General programming communities, such as The Odin Project's Discord or the r/learnprogramming subreddit, welcome beginners asking Python and Git questions. Read their rules first.
- **Post weekly.** A short weekly note on a blog, social media, or later in your GitHub learning journal ("This week I learned..., I got stuck on..., next week I'll...") works surprisingly well, because you'll want to have something to write.
- **Schedule it.** Put study hours on your calendar like appointments. You'll do this formally in the "Learning Plan" project at the end of this section.
